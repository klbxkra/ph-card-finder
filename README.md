# PH Card Finder

A single-page app that recommends Philippine credit cards from a few bracketed answers. All the math runs in the browser and nothing a user enters is saved or sent.

- Live site: https://klbxkra.github.io/ph-card-finder/
- Private Claude artifact (preview): https://claude.ai/artifact/YFnrdmpdbMQhpGMVajabAU

## Files

| File | What it is |
| --- | --- |
| `index.html` | The app: layout, styles, eligibility, value, ratings, upgrade paths, sort and filters, the 6-card compare view, the promo tracker and the What changed page. Written for the Claude artifact, which adds the `<html>`/`<head>` wrapper when it publishes. The only things it stores are the viewer's light/dark choice and the MoneyMax-offers switch, in their own browser. |
| `data.js` | Every card, bank note, document list, apply link, promo and source. Sets `window.PHCC_DATA`. The only file a data refresh should touch. |
| `history.js` | Card-level change log shown on the What changed page. Sets `window.PHCC_HISTORY`. Generated by `scripts/record-changes.js`; don't edit by hand. |
| `scripts/record-changes.js` | Compares `data.js` with the last committed version and adds an entry to `history.js` (cards added or removed, fee, income, forex, interest, rewards, apply link and promo changes). `--rebuild` regenerates the whole file from git history. |
| `scripts/check-data.js` | Validates `data.js`: schema, dates, source links, apply links on bank domains, the BSP 3% interest cap. Run before publishing. |
| `scripts/build-site.js` | Writes `docs/` for GitHub Pages: `index.html` wrapped in a full HTML document with link-preview tags, plus `data.js`, `history.js`, the manifest, the service worker and `assets/`. |
| `scripts/make-images.py` | Draws the app icons and the link-preview image into `assets/` (needs Pillow). Only rerun if the look changes. |
| `manifest.webmanifest`, `sw.js` | Let people install the site as an app. The service worker loads everything from the network first and only falls back to its cache when offline, so refreshes show up on the next visit. It only registers on github.io. |
| `assets/` | App icons and `og.png`, the image shown when a link is shared. |
| `docs/` | Built site that GitHub Pages serves. Don't edit by hand; run the build script. |
| `.github/workflows/pages.yml` | Checks the data, rebuilds `docs/` and deploys to GitHub Pages on every push to `main`. |

## Refreshing the data

A scheduled task, **PH card data refresh**, runs on the 1st of each month at 9:00 AM. It runs while the Claude desktop app is open, or at the next launch if the app was closed. It:

1. Re-checks each card on the bank's own site first, then on comparison sites (taxcalculator.com.ph, MoneyMax).
2. Updates `data.js`: figures, `checked` dates, promos and end dates, apply links, new or discontinued cards.
3. Bumps `meta.version` and `meta.dataAsOf` and adds a changelog line.
4. Runs `node scripts/check-data.js` and stops if it fails.
5. Runs `node scripts/record-changes.js` so the What changed page lists the card-level changes.
6. Republishes the artifact to the same link.
7. Runs `node scripts/build-site.js`, commits and pushes to `main`. The Pages workflow redeploys from that push.

To refresh by hand, ask Claude in this folder to "refresh the card data", or use **Run now** on the task.

## GitHub Pages

Settings → Pages → Build and deployment → Source: **GitHub Actions**. The workflow in `.github/workflows/pages.yml` runs on every push to `main`: it runs `scripts/check-data.js` (a failing check stops the deploy), rebuilds `docs/`, and publishes it. You can also start it by hand from the Actions tab.

## Corrections

Each card has a **Report a correction** link that opens a pre-filled GitHub issue on this repo. Reporting needs a free GitHub account. Check the issue against the bank's site before changing `data.js`.

## Data rules

- Change only what you verified. Set `checked` to the date you looked and `via` to `official` or `aggregator`.
- Never guess a number. If sources disagree or a figure isn't published, say so in `fee.note`, `incomeNote` or `flags`.
- Promos need an `until` date (or `null` if the bank shows none). The app marks promos as ended on its own.
- Apply links must go to the bank's own domain. `check-data.js` warns about any other host.
- Store options in `ecosystems` only list stores where at least one card pays extra.
- Offers that only apply when you sign up through a third party (MoneyMax) use `src: "mm"` or `"mmub"`. The app hides them unless the viewer turns on **Show MoneyMax offers**.
- Community notes (`community`, `communityTips`) must cite a `kind: "community"` source and are shown as cardholder reports, not bank facts.
